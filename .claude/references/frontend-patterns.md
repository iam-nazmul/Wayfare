# Frontend patterns

React 19 + TypeScript + Vite 7 + Tailwind 4. Authority: [SPEC.md](../../SPEC.md) §10.

## Structure

```
src/
├── api/            # GENERATED types + fetch wrapper + query hooks
├── components/     # design-system primitives only, no domain knowledge
├── features/<domain>/   # search, booking, checkin, manage, agency, ops
│   ├── components/ hooks/ types.ts index.ts
│   └── README.md   # for developers/agents
├── lib/            # analytics.ts events.ts money.ts dates.ts auth.ts
└── styles/
```

A component in `components/` that imports from `features/` is backwards. A feature importing
another feature's internals is backwards — go through its `index.ts`.

## API client

`src/api/schema.d.ts` is generated by `openapi-typescript` from `/api/schema/`. Never hand-write
request/response types; run `make schema`.

The fetch wrapper (`src/api/client.ts`) owns:
- Bearer token attachment and a **single in-flight refresh** with queued retries.
- `Idempotency-Key` generation for mutating calls.
- RFC 9457 parsing into a typed `ProblemDetail`, so components render `title` + field `errors`.

## Server state — TanStack Query

Query keys are tuples built by factory functions in `src/api/keys.ts`, never inline strings:

```ts
export const keys = {
  search: (params: SearchParams) => ["search", params] as const,
  booking: (pnr: string) => ["booking", pnr] as const,
  seatmap: (pnr: string, segmentId: string) => ["seatmap", pnr, segmentId] as const,
};
```

| Data | `staleTime` | Notes |
|---|---|---|
| Search results | 60 s | Matches the server cache TTL |
| Catalog (airports, airlines) | 24 h | Also persisted to localStorage |
| Booking detail | 0 | `refetchInterval: 5000` while `PENDING_TICKETING` |
| Seat map | 30 s | Refetch on window focus |

Mutations invalidate by key; they do not manually patch the cache except for optimistic seat
selection, which rolls back on error.

## Client state — Zustand

One store for the booking wizard: selected offer, passenger draft, extras cart, currency.
Persisted to `sessionStorage` so a mid-flow refresh does not lose progress. Everything else that
comes from the server stays in TanStack Query — do not mirror server data into Zustand.

## Forms

`react-hook-form` + `zod`. Schemas live beside the form in the feature. Validation rules that the
server also enforces (pax type by DOB, infant-adult binding, document expiry) are derived from the
OpenAPI schema where possible so the two cannot drift.

## Money and dates

`lib/money.ts` — `formatMoney({amount, currency}, locale)`. No inline `toFixed(2)`, no arithmetic on
display strings. Any conversion shows the original currency in a tooltip.

`lib/dates.ts` — flight times render in **airport-local time with the tz abbreviation**, never in
the viewer's timezone. Durations come from the API (`duration_minutes`), never recomputed client-side.

## Analytics

```ts
track("offer_selected", { offer_id, origin, destination, amount, currency });
```

Event names come from the typed union in `lib/events.ts` — adding one means extending the union, so
ad-hoc names fail type-check. The queue flushes on 10 events, 5 s idle, route change, or
`visibilitychange → hidden` via `sendBeacon`. Respect `doNotTrack` and the consent flag.

## Tailwind 4

`@import "tailwindcss";` in `src/index.css`; design tokens in `@theme`. Colours, spacing, and radii
come from tokens — no arbitrary hex values in components. Dark mode via `prefers-color-scheme` plus
a manual toggle, both driven by CSS variables.

## Accessibility (WCAG 2.2 AA — not optional)

- Seat map and fare calendar need keyboard paths and list-based fallbacks.
- `aria-live="polite"` on price and availability changes, and on the hold countdown.
- Focus rings visible; contrast ≥ 4.5:1; status never encoded by colour alone.
- Every interactive element reachable by Tab in visual order.

## Performance

Route-level `React.lazy` for the three trees (storefront / agency / ops). Virtualise result lists
beyond 50 rows. Search results stream in with skeletons — never a blank screen.
